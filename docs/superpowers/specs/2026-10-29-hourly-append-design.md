# Resume the same hourly MP3 and CUE

The user explicitly requests one file per clock hour: Stop/Rec or automatic recovery appends existing current-hour MP3 and CUE; when absent create them. Missing broadcast seconds/minutes are omitted, without silence insertion. The next clock hour uses its ordinary base name, never a session suffix. This supersedes the previous suffix rule in AGENTS.md. Existing historical suffixed files remain untouched.

FFmpeg's segment muxer cannot append. Keep continuous FFmpeg input/encoding, send tagless MP3 to stdout, route complete MPEG frames in a bounded Python output worker into append-opened clock-period files. Disable bit reservoir for independently decodable new-hour files. Scan only the selected existing MP3 on reopen to recover actual frame duration, validate rate/channels, repair an incomplete trailing frame where safe, and refresh old Xing duration fields. Never reencode the archive or read whole audio files into memory. Invalid or incompatible existing audio/CUE must fail with a clear error, preserving completed data; never silently choose a suffix or truncate valid audio.

Recover only current CUE (at most 99 tracks), preserve recorded prefix, map each new capture span from wall timestamps into actual appended audio offsets. Reject history from before the resumed span; playbackinfo may seed the current title at the append seam. Pauses do not become CUE gaps. Closed hours never change. New files use the start of the configured clock period for filename placeholders, including a start at18:02 naming18:00.

Preserve UI layout, settings, metadata independence, schedule, autostart and single instance. No new dependencies or intermediate audio files. Non-split mode retains its actual start-timestamp basename and reuses it across automatic reconnection. If a later manual start expands to an existing name, append that same file too; the user's no-suffix rule applies globally. Retention protects active files. Test same-hour manual/app/encoder restart, next hour/day, missing files, incomplete tails, old Xing tags, CUE history/99 tracks, disk failures and stop/close during output.

CUE durability: persist accepted MP3 frames before fsync of any CUE index referencing them. Metadata ahead of encoded audio waits in a bounded pending queue; keep the latest observed title separately for hour/reconnect seeding. Validate the resumed first frame before saving a new seam. If audio is absent/empty but CUE exists, preserve the orphan metadata in a .cue.orphan backup and create a new zero-based pair.
