# RadioRecorder Python 0.5.1 — обновление

Новая версия Python-проекта сохраняет работу DirectShow и RadioBOSS HTTP API, как в 0.4.1. Добавлены дополнительные аудиовходы Windows из PortAudio (драйвер и API скрыты в названии устройства), измерение уровня при Play и повышенный автозапуск Windows через Планировщик заданий.

**Вход Windows → PCM → FFmpeg → MP3. RadioBOSS HTTP API → только CUE.**

В настройках «Источник записи» можно выбрать как прежнее имя DirectShow (работает через FFmpeg), так и вход Windows с обычным именем устройства (запись из Windows → поток PCM → FFmpeg). Для дополнительных PortAudio-входов программа должна иметь доступ к звукозаписывающему устройству, частота и каналы должны поддерживаться драйвером. Для мониторинга нажимай ▶; индикатор уровня показывает dBFS (-60…0). Повторное нажатие выключает прослушивание.

«Запускать с Windows» даёт обычный автозапуск. Если дополнительно включить «Запускать с правами администратора», программа попросит UAC при создании задания Планировщика и затем будет стартовать без новых запросов при входе текущего пользователя. Для отключения также может потребоваться подтверждение UAC. Не повышай права без необходимости.

ВНИМАНИЕ: GitHub-сборка и тесты не заменяют проверку с реальными Windows-драйверами; перед круглосуточной эксплуатацией проверь запись, CUE и переподключение входа.

# RadioRecorder 0.4.1 — быстрый старт

**Windows 10/11 x64.** Эта программа не является копией исходников RadioLogger: это самостоятельно разработанный совместимый по назначению рекордер с похожим интерфейсом и CUE.

## Установка без Python

### Вариант 1 — готовая папка после сборки
1. Распакуй папку `dist\RadioRecorder`, сохранив всю структуру вместе с `_internal`, `assets` и `ffmpeg.exe` (если он был включён в сборку).
2. Запусти **RadioRecorder.exe**. Установка Python отдельно не нужна.

### Вариант 2 — собрать EXE на Windows самому
1. Установи **Python 3.11+ x64**.
2. Положи `ffmpeg.exe` рядом с `app.py` (или в корень проекта).
3. Дважды щёлкни **build_windows.bat**. Он установит зависимости и соберёт переносимую папку `dist\RadioRecorder`.
4. После сборки запускай **dist\RadioRecorder\RadioRecorder.exe**.
4. Нажми **Настройки** → «Устройство Windows», затем **Обновить список устройств** и выбери именно тот вход, на который действительно приходит звук: `Line In (Realtek)`, `Line 1 (Virtual Audio Cable)`, `USB AUDIO CODEC` и т. п. Устройство должно присутствовать в системе и не быть занятым в монопольном режиме.
5. Выбери MP3: например, **48000 Гц**, **128 kbps**, **моно** (или стерео).
6. Включи разделение **каждые 60 минут**. При выборе 60 минут границы строго привязаны к началу часов Windows: если запись началась в 11:23, первая пара файлов содержит 11:23–12:00, вторая 12:00–13:00, третья 13:00–14:00. Кодировщик не перезапускается при смене часа. Введи шаблон `%d-%m-%y_%hh-%mm` для файлов вроде `27-10-2026_11-00.mp3`.
7. Настрой получение метаданных от RadioBOSS, как ниже, и нажми **Rec** (красный кружок загорится при записи). Для автоматической записи по планировщику нажми **Авто**.

## Режим «Авто» и ручная остановка (изменено в 0.4.1)

- **Авто** включено: RadioRecorder записывает в часы, разрешённые недельным планировщиком, и автоматически запускает запись после открытия программы, если текущий час разрешён.
- **Stop** останавливает **только текущую запись** и **не снимает галочку Авто**. Чтобы запись не возобновилась через секунду, вручную остановленный час пропускается до следующего начала часа по системному времени Windows. Пример: Stop в 11:23 → ожидание до 12:00; запись запускается в 12:00 только если этот час отмечен зелёным.
- Если час 12:00–13:00 запрещён, программа продолжает ожидание до следующего разрешённого часа, например до 13:00.
- **Rec** вручную запускает запись и снимает паузу текущего часа. Для полного отключения автоматического режима нужно **снять галочку Авто** — она сохраняется между перезапусками.
- Ручная пауза после Stop не сохраняется между запусками: при следующем открытии программа заново следует планировщику. Для автоматического запуска вместе с Windows включи соответствующий пункт в настройках.
- Если аудиоустройство не настроено или занято, автоматический запуск повторяется не чаще раза в 30 секунд; ошибка показывается в журнале.

## Прослушивание потока через выбранные колонки (новое в 0.2)

1. Открой **Настройки → Воспроизведение / прослушивание**.
2. В поле «Устройство вывода звука» выбери наушники, колонки или **Default** (выход по умолчанию в Windows). Нажми «Обновить устройства воспроизведения», если только что подключил устройство.
3. Если записываешь с **Windows Line In**, оставь «Вход для прослушивания» = **Auto**. Программа постарается сопоставить вход FFmpeg с названием устройства Windows. Если появится сообщение «Не найден вход для прослушивания», выбери тот же вход вручную в этом поле.
4. Нажми кнопку **▶ рядом с таймером в главном окне**. Первое нажатие включает **прослушивание**, второе нажатие на **ту же кнопку ▶** выключает его. Во время мониторинга кнопка зелёная. **Play никогда не запускает запись**. **Rec** и **Stop** ниже управляют только MP3-записью.
5. В активной записи кружок возле **Rec** становится **красным**, в режиме ожидания он серый. Кружок и квадрат Stop имеют одинаковый габарит 12×12 пикселей.

Для запуска из исходников предварительно установи `py -3.12 -m pip install -r requirements.txt`. В готовом архиве Windows отдельная установка Python или sounddevice не нужна. Мониторинг использует отдельный аудиоклиент Windows в общем режиме и может не включиться на эксклюзивно захваченном входе; **даже если мониторинг не сработал, текущая запись не останавливается**.

**Важно:** если источник записи — Windows Line In, ты слушаешь именно вход Line In, а не ICY-метаданные RadioBOSS. Если источник записи — HTTP-аудиопоток, ▶ воспроизводит сам HTTP-аудиопоток.

## Автоматическое удаление старых файлов (изменено в 0.3)

В **Настройки → Автоудаление** включи «Удалять записи старше» и укажи срок хранения **N дней (не менее 90)** (по умолчанию включено, 90 дней).

- **Раз в календарный день после 00:00 по времени Windows**, пока идёт запись, программа очищает папку архива. Если запись началась после полуночи, очистка выполняется при старте записи, если сегодня её ещё не было. При непрерывной записи следующее удаление произойдёт вскоре после следующей полуночи.
- Проверяется **всё содержимое указанной папки на верхнем уровне**: любые старые файлы `.mp3`, `.cue`, `.txt`, `.log`, `.wav` и других типов удаляются **безвозвратно**, даже без пары MP3/CUE. **Не помещай посторонние важные файлы в эту папку.**
- Не обрабатываются вложенные папки, символические ссылки, текущий MP3 и CUE, а также несколько недавно созданных сегментов, чьи CUE ещё обновляются. Папка с самой программой, корень диска и домашняя директория защищены от очистки.
- Возраст считается по **дате последнего изменения файла**, относительно полуночи локального времени. При N=90 и дате 27 октября файлы с временем изменения **до 00:00 29 июля** будут удалены. Файлы от 29 июля останутся до следующей ежедневной очистки.
- Дата последней очистки хранится в `%LOCALAPPDATA%\RadioRecorder\retention_state.json`. Повторный запуск в тот же день не запускает очистку снова. Этот файл не содержит персональных данных или паролей.
- Менять срок хранения и переключатель автоудаления можно во время записи — изменения вступают в силу сразу; но смена папки архива требует перезапустить саму запись.

**Важно:** автоудаление отключается через настройки. Удалённые файлы нельзя восстановить средствами RadioRecorder; перед первым включением функции лучше проверить, что выбрана отдельная папка, содержащая только архив эфира.

## Настройка CUE по HTTP API RadioBOSS (рекомендуется)

На компьютере с RadioBOSS включи «Remote Control API» в настройках. Укажи порт (часто `9001`), пользователя и пароль, разреши сетевое подключение через брандмауэр Windows. Если программа запущена на другом компьютере, используй IP RadioBOSS, **не** `127.0.0.1`.

Например, если RadioBOSS работает на `192.168.2.170`, укажи в RadioRecorder:

- «Метаданные»: **HTTP API**.
- «Адрес RadioBOSS API»: `http://192.168.2.170:9001`.
- «Пароль API»: пароль, который ты задал в RadioBOSS.

Проверь запрос с компьютера, где будет запускаться RadioRecorder: `http://192.168.2.170:9001/?pass=ВАШ_ПАРОЛЬ&action=playbackinfo`. Вместо пароля подставь свой. Не выкладывай полный URL с паролем в интернете.

RadioRecorder читает `playbackinfo` и `getlastplayed`, затем создаёт CUE с названиями треков и их временными позициями. Данные звука в этом режиме берутся **только** из аудиовхода Windows. API не скачивает звук.

**Если хочешь получать названия прямо из потока**, вместо API выбери **ICY из потока** и укажи `http://192.168.2.170:8000/`. В этом режиме программа соединяется с трансляцией, читает и **отбрасывает** аудиобайты, извлекая из потока `StreamTitle`. Звук для MP3 по-прежнему берётся из выбранного линейного входа. Это работает только если сервер передаёт `icy-metaint` и названия. ICY обычно менее точен по времени, чем API RadioBOSS.

## Проверка

В архиве должны появиться два файла с одинаковым базовым именем:

```
27-10-2026_11-00.mp3
27-10-2026_11-00.cue
```

В CUE будет заголовок `REM DATE`, `REM COMMENT`, `FILE`, а также блоки `TRACK XX AUDIO` с `TITLE` и `INDEX 01`. Начальная позиция нового файла — `00:00:00`, даже если в этот момент проигрывается длинный трек, начатый в предыдущем часе.

**Время**: точность абсолютного совмещения зависит от системных часов двух машин, задержки линейного входа, обработки RadioBOSS и настроек потоков. Для компенсации вручную выставляется «Коррекция времени CUE, сек», которая сдвигает временные метки треков. Точность шкалы CUE — 1/75 секунды, но это **не означает**, что метки событий поступают с такой точностью. API `getlastplayed` предоставляет время начала обычно с точностью до секунды.

## Проблемы

- **Не виден аудиовход**: проверь настройки Windows «Звук» → «Запись», доступ приложений к микрофону, занятость устройства, 64-битный `ffmpeg.exe` рядом с программой.
- **Нет CUE или только «Неизвестный трек»**: проверь IP и порт API, пароль, активность воспроизведения, лог программы. Порт `8000` для музыкального потока и `9001` для API — разные назначения.
- **Время CUE не совпадает с MP3**: синхронизируй системные часы компьютеров и откорректируй смещение в настройках. Для передачи названий через API оба компьютера должны работать в согласованном часовом поясе.
- **Запись не начинается**: проверь `ffmpeg.exe`, физическое устройство ввода и лог. Если устройство занято, закрой приложение, которое захватило его в монопольном режиме.
- **Программа переносится** целиком, включая `_internal` и `ffmpeg.exe`. Не пытайся запускать один `.exe` без этих файлов.

Настройки сохраняются как `%LOCALAPPDATA%\RadioRecorder\settings.json` (старые параметры автоматически читаются из папки EXE, если новый файл ещё не создан). **Пароль API и SMTP хранится там в открытом виде**: защищай папку и никогда не загружай `settings.json` в публичный репозиторий.

## Текущее состояние

Версия 0.3 — обновление первой сборки для проверки в реальной Windows-среде с RadioBOSS. Поддерживает MP3, входы DirectShow, API/ICY, отдельный CUE для каждого фрагмента, планировщик по дням и часам, архив, автоудаление, автостарт, перезапуск кодировщика и опциональные email-уведомления о тишине.

Возможности выбора выхода Windows и красного индикатора активной записи сохранены. Пока **нет** значка в системном трее и аппаратно-синхронизированной точности CUE до кадра. Не заявляется стопроцентная побайтовая совместимость с оригинальной программой на непроверенном ПК. Настоящую проверку нужно выполнить на Windows с твоим линейным входом и RadioBOSS.

## Обновление 0.5.4 — надёжность записи и настройки

1. В автоудалении теперь можно установить **от 90 до 3650 дней**. Значения меньше 90 недопустимы даже при изменении JSON вручную. При обновлении старого значения 7 или 30 дней оно поднимется до 90.
2. При выбранном стереорежиме рекордер сначала проверяет, открывается ли реальный Windows-вход. Если у входа доступно только моно, автоматически использует 1 канал и пишет об этом в журнал. Если частота входа не поддерживается, пробует частоту устройства, затем FFmpeg приводит поток к частоте MP3 из настроек.
3. При Play для MME/DirectSound перебираются совместимые частоты и варианты каналов; вход и выход могут иметь разное число каналов. Если этот интерфейс по-прежнему не работает, выбери **Windows WASAPI** в настройках.
4. Настройки и служебный файл автоочистки переносятся в `%LOCALAPPDATA%\RadioRecorder\`. Это устраняет необходимость записывать их рядом с EXE в `C:\Program Files`. Архив MP3/CUE по-прежнему сохраняется в указанную папку.
5. Запись проверяет доступность папки архива до запуска и сообщает об отказе, вместо того чтобы показывать «Rec», когда MP3 ещё не может создаваться. Для доступа к устройствам проверь разрешение Windows на использование микрофона приложениями и отсутствие эксклюзивного захвата.
6. Если включено **«Спрашивать при закрытии»**, подтверждение требуется даже без активной записи.

Ограничения: тесты с имитацией Windows-аудиоустройств проходят, но работу каждого физического DirectSound/MME/USB-драйвера нужно проверять на конкретном компьютере.

- Галочка **«Запуск с правами администратора»** доступна всегда. Включение её автоматически включает «Запускать с Windows», так как этот режим применяется к автозапуску через Планировщик заданий. Сама установка задания запрашивает UAC при сохранении настроек. Отключение автозапуска снимает и флаг повышенных прав.
- Для **новой установки** срок автоудаления по умолчанию **90 дней**. Сроки, уже сохранённые пользователем (например, 365 дней), не заменяются без его согласия — измени их в настройках один раз.
- Размеры окон и расположение разделов оставлены от 0.5.6, планировщик не изменён.

## Обновление 0.5.9 — имя файла и сворачивание с Windows

Под полем **Формат имени файла** показывается живой пример конечного MP3-имени. Когда меняешь расположение переменных, пример меняется немедленно. Используй `%d` (день), `%m` (месяц), `%y` (4 цифры года), `%hh` (час), `%mm` (минута), `%ss` (секунда). Пример: `%y%m%d-%hh%mm%ss` → `20261027-112345.mp3`. По умолчанию остаётся `%d-%m-%y_%hh-%mm` — секунды можно добавить самостоятельно. Парный CUE получает то же имя, но расширение `.cue`.

Галочка **«Сворачивать при автозапуске»** работает только при автозапуске с Windows. При обычном ручном открытии RadioRecorder окно не сворачивается. Для старой регистрации автозапуска, сделанной до 0.5.9, **один раз** выключи «Запускать с Windows» в настройках и сохрани; затем включи и снова сохрани. Так Windows получит новое значение `--autostart`. Для повышенного автозапуска потребуется согласие UAC при повторной регистрации задания.

Окно настроек стало уже: убрано лишнее поле справа без изменения двухколоночного расположения разделов. По умолчанию для новой установки удаляются файлы старше 90 дней; уже сохранённый срок хранения НЕ меняется при обновлении.


## Изменение 0.6.0 — только актуальный CUE

Программа создаёт CUE к текущему MP3, обновляет его во время записи и после начала следующего часового файла **больше не меняет завершённый CUE**. История MP3 и CUE не хранится в памяти рекордера. Архив доступен как список файлов в выбранной папке; сами аудиоданные не загружаются в память. Windows показывает время создания CUE в момент начала соответствующей записи, а время изменения — при последней правке этого CUE в том же часу. Запоздавшие метаданные уже завершённого часа сознательно игнорируются.


## Изменение 0.6.1 — безопасность записи и очистки

При ежедневной очистке удаляются только `.mp3` и `.cue`, которым больше установленного срока хранения (не менее 90 дней). Посторонние расширения и подкаталоги не затрагиваются. Старые MP3/CUE, записанные **другой программой** в этой же папке, всё ещё могут быть удалены: лучше выделить RadioRecorder отдельную папку.

Если имя часового файла уже занято, RadioRecorder заранее выбирает суффикс `_2`, `_3` и далее для **всего нового сеанса записи**, не прерывая непрерывный поток FFmpeg. Шаблон имени обязан различать часы (в обычном режиме с датой и временем); иначе программа покажет ошибку перед записью.

CUE активного часа обновляется в том же файле; обычно новые строки добавляются в конец. Полностью устранить риск повреждения **последней незавершённой строки** при пропадании питания нельзя, но уже закрытые CUE больше не затрагиваются. Для анализа отказов используй `%LOCALAPPDATA%\RadioRecorder\radiorecorder.log`. Радиозащита свободного места останавливает запись при менее 256 МиБ, чтобы запись не заполнила системный диск.

На Windows FFmpeg по возможности связывается с жизненным циклом приложения через Job Object. Если Windows запретит это, информация появится в журнале; немедленная аварийная остановка дочернего FFmpeg в таком случае не гарантируется. Задание автозапуска в Планировщике конфигурируется без блокировки главного окна. Настройки прошлых версий не сбрасываются при обновлении.
